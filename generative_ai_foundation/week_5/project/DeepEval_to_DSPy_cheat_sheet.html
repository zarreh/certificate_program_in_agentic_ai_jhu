DeepEval - what you already know  →  DSPy - what the project needs

From DeepEval to DSPy - Bridge Cheat Sheet

A practical guide for moving from DeepEval to DSPy

Purpose and scope

DeepEval and DSPy support different parts of an evaluation-driven LLM workflow:

  • DeepEval provides test cases, evaluation metrics, and GEPA workflows around prompts or model callbacks.
  • DSPy represents an LLM workflow as typed signatures and callable modules, then uses an optimizer such as GEPA to improve the instructions inside that workflow.

GEPA's central loop remains the same in both tools: run candidates, score them, collect useful feedback, revise the instructions, and retain better candidates. This guide explains how that same loop is expressed in DSPy for the prompt-optimization section of the DualLens project. It is intentionally focused and is not a complete DSPy course. The preceding project sections provide the retriever, format_context, gold dataset, and baseline evaluation tables. The three DSPy building blocks needed here are:

  • Signature: a typed prompt contract; its docstring is the instruction text.
  • Predict: a callable generator that uses a Signature and returns a prediction (for this project, read the answer as pred.answer).
  • Module: a Python pipeline whose forward() method connects retrieval to Predict.

The project pins dspy==3.2.1. Run the notebook cells in order and use the exact project variable/function names. The examples below explain the DSPy shape; the project notebook provides the surrounding code skeleton.

# Concept DeepEval DSPy (Project) What to watch for
1 The prompt itself Prompt(text_template="...{input}...") - a string template class GroundedQA(dspy.Signature): """<prompt text goes here>""" - the docstring is the prompt It's a class, not a string. InputField(desc=...) / OutputField(desc=...) descriptions are also part of the prompt that GEPA can rewrite.
2 One test case Golden(input=..., context=..., additional_metadata=...) dspy.Example(question=..., context=..., answer=...).with_inputs("question", "context") .with_inputs(...) is required - it tells DSPy which fields are inputs vs. the labelled answer. No DeepEval equivalent; easy to forget.
3 Running one candidate on one example You write model_callback(prompt, golden) and call llm_call(...) yourself You write the project's Module.forward(self, question, ticker_hint); DSPy calls it with the example's declared inputs Retrieval (your ChromaDB filtered search) must live inside forward(). GEPA evaluates the complete pipeline, but it rewrites the generation instructions-not the Python retrieval code.
4 Scoring a candidate metric.measure(test_case), then read metric.score / metric.reason A plain function such as def gepa_metric(example, pred, trace=None, pred_name=None, pred_trace=None) The extra GEPA arguments are optional, but the project skeleton includes them. Return dspy.Prediction(score=..., feedback=...), not a float or dict.
5 Giving GEPA feedback to reflect on Comes from the metric object's .reason (per-metric) You must build the feedback= string yourself inside the metric function A bare return score (float) still runs - but reflection gets nothing to read, so prompt rewrites degrade toward random search.
6 The optimizer object PromptOptimizer(algorithm=GEPA(iterations=, pareto_size=, minibatch_size=), model_callback=, metrics=, optimizer_model=) dspy.teleprompt.GEPA(metric=, reflection_lm=, auto=... ) DSPy's GEPA needs a separate reflection_lm - don't reuse the task LM object.
7 Global model wiring Model passed explicitly at each call site (model_callback, optimizer_model=) dspy.settings.configure(lm=task_lm) - set once, used implicitly everywhere If you skip this, the first dspy.Predict(...) call fails with an opaque "no LM configured" error, not at config time.
8 Kicking off optimization optimizer.optimize(prompt=starting_prompt, goldens=gold_goldens[:10]) → returns a prompt-like object gepa.compile(student=module, trainset=dspy_trainset) → returns a compiled Module The return value is an object you can call, not a template string.
9 Reading the optimized prompt back out optimised_result.text_template compiled.predictors()[i].signature.instructions (rewritten docstring) and .demos (few-shot examples GEPA attached) There is no single .text_template. You inspect predictors on the compiled Module.
10 Train / test split A held-out set can be evaluated after optimization dspy_trainset passed to .compile(); dspy_testset held out and compared afterward Conceptually identical to ML train/test - DSPy makes trainset an explicit argument.

2. Minimal working shapes (adapt these to the project skeleton)DSPy code

The snippets below show the project-specific shape. They are intentionally small; the project notebook supplies the existing retriever and evaluation data.

Signature (the prompt):

class GroundedQA(dspy.Signature):
    """Answer the question using ONLY the provided context.
    If the context does not contain the answer, say you don't know."""
    context:  str = dspy.InputField(desc="Retrieved passages")
    question: str = dspy.InputField(desc="The user's question")
    answer:   str = dspy.OutputField(desc="Answer grounded strictly in context")

Module (the pipeline GEPA actually optimizes):

class GroundedRAG(dspy.Module):
    def __init__(self):
        super().__init__()
        self.generate = dspy.Predict(GroundedQA)

    def forward(self, question, ticker_hint):
        # Retrieval is fixed Python code; GEPA sees its output while scoring candidates.
        docs = retrieve(question, company=ticker_hint, k=TOP_K)
        context = format_context(docs)
        return self.generate(context=context, question=question)

Metric (score + feedback GEPA reflects on):

def gepa_metric(example, pred, trace=None, pred_name=None, pred_trace=None):
    answer = (pred.answer or "").strip()
    hit = example.expected_substring.lower() in answer.lower()
    score = 1.0 if hit else 0.0
    if hit and len(answer.split()) > 80:
        score = min(score, 0.7)   # penalize keyword-stuffed long answers
    feedback = "Correct and concise." if score == 1.0 else \
               f"Missing expected content: '{example.expected_substring}'."
    return dspy.Prediction(score=score, feedback=feedback)

expected_substring is metric-only ground truth. Do not mark it as an input, or the program could see the answer it is supposed to discover.

LM config + compile:

task_lm = dspy.LM(
    model="openai/gpt-4o-mini", temperature=0.1,
    api_key=os.environ["OPENAI_API_KEY"], api_base=os.environ["OPENAI_BASE_URL"],
)
reflection_lm = dspy.LM(
    model="openai/gpt-4o-mini", temperature=1.0,

2.1 The complete project-shaped flow

This is the direct DeepEval-to-DSPy translation used by the project notebook:

def make_example(row):
    return dspy.Example(
        question=row["question"], ticker_hint=row["ticker_hint"],
        expected_substring=row["expected_substring"],
    ).with_inputs("question", "ticker_hint")

class GroundedQA(dspy.Signature):
    """Answer using only the supplied context. If it is insufficient, say exactly
    "I don't know." Name the specific product or initiative when the context provides it."""
    context: str = dspy.InputField()
    question: str = dspy.InputField()
    answer: str = dspy.OutputField()

class GroundedRAG(dspy.Module):
    def __init__(self, k=TOP_K):
        super().__init__()
        self.k = k
        self.generate = dspy.Predict(GroundedQA)

    def forward(self, question, ticker_hint):
        docs = retrieve(question, company=ticker_hint, k=self.k)
        return self.generate(context=format_context(docs), question=question)

gepa = GEPA(metric=gepa_metric, reflection_lm=reflection_lm,
            auto="light", track_stats=True, seed=42)
compiled = gepa.compile(student=GroundedRAG(), trainset=dspy_trainset)

# Use the held-out set only after compilation.
for example in dspy_testset:
    prediction = compiled(**example.inputs())
    print(prediction.answer)

The trainset is used for optimization. The held-out dspy_testset is used only for the before/after comparison, just as in a standard evaluation experiment.

3. Common errors → fixDSPy

Error / symptom Cause Fix
Metric invocation/signature error Metric function does not accept the optional GEPA arguments used by the installed version Use the project shape gepa_metric(example, pred, trace=None, pred_name=None, pred_trace=None)
AttributeError: 'GroundedRAG' object has no attribute 'inputs' on an Example Forgot .with_inputs(...) when building dspy.Example Call .with_inputs("question", "ticker_hint") on every project example
GEPA runs but the prompt barely changes / result looks random Metric returns a bare float instead of dspy.Prediction(score=, feedback=) Always wrap the return, and make feedback a genuinely informative sentence
ContextWindowExceeded / "No LM is loaded" the first time you call dspy.Predict dspy.settings.configure(lm=...) never ran, or ran after the first call Run dspy.settings.configure(lm=task_lm) immediately after creating task_lm, before any Predict
Looking for .text_template on the GEPA result and getting AttributeError Carrying over the DeepEval mental model - DSPy's GEPA returns a compiled Module, not a prompt object Use compiled.predictors() / .named_predictors() and read .signature.instructions
Reflection doesn't seem to improve anything over iterations reflection_lm not passed, or accidentally set to the same object as task_lm with temperature=0 Pass a distinct dspy.LM(...) with higher temperature as reflection_lm
GEPA "optimizes" but ignores your retrieval logic Retrieval called outside forward(), with only the answer-generation step wrapped Move retrieval inside Module.forward() so it's part of what GEPA scores each iteration
NameError for retrieve, format_context, TOP_K, or dspy_trainset Project setup cells were skipped, or code was copied out of context Run the project notebook in order; these are supplied by earlier project sections
The model sees expected_substring It was included in .with_inputs(...) Use only .with_inputs("question", "ticker_hint"); keep the label for the metric
dspy.LM cannot reach the configured endpoint A custom API base URL/key was omitted Pass the notebook's OPENAI_API_KEY and OPENAI_BASE_URL as shown above

4. Saving and checking the result DSPy

The compiled result is a callable dspy.Module, not a prompt string. The project persists it with:

compiled.save("gepa_optimised_rag.json")

for name, predictor in compiled.named_predictors():
    print(name, predictor.signature.instructions)
    print("demos:", len(getattr(predictor, "demos", [])))

Keep the notebook's pinned dspy==3.2.1 when reproducing the run. If a different DSPy version changes GEPA arguments or predictor-inspection methods, return to the project-pinned environment before debugging the prompt itself.

5. One-line mental model

DeepEval's GEPA optimizes a template string, driven by an external callback you write.

DSPy's GEPA optimizes a live Python object (your Module), by rewriting the docstring of a Signature class embedded inside it - and it needs your metric function to hand back both a score AND a sentence of feedback, or reflection has nothing to work with.
